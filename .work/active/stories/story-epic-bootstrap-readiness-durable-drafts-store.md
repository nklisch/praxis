# Drafts table + `DraftStore` port and SQLite adapter

## Scope

Land the foundation pieces of the durable-drafts feature: the schema, the
generated migration, and a self-contained `DraftStore` port + SQLite
adapter. No `BootstrapServiceImpl` changes in this story — that's the
sibling integration story.

## Units implemented

- **Unit 1** (`drafts` table schema + Drizzle migration). See the design
  in `epic-bootstrap-readiness-durable-drafts.md`.
- **Unit 2** (`DraftStore` interface + `SqliteDraftStore` impl).
- **Unit 5 partial** — store-level tests
  (`packages/core/src/__tests__/draft-store.test.ts`).

## Files touched

- `packages/core/src/schema.ts` — add `drafts` table; register in
  `coreSchema`.
- `drizzle/0009_<generated>.sql` — `pnpm db:generate` produces this.
- `packages/core/src/services/draft-store.ts` (new) — `DraftStore` port
  + `SqliteDraftStore` adapter.
- `packages/core/src/services/index.ts` — export `DraftStore` and
  `SqliteDraftStore` (the integration story consumes them).
- `packages/core/src/__tests__/draft-store.test.ts` (new) — round-trip,
  list, mark-confirmed-tx-rollback, mark-discarded, sweep-stale tests.

## Acceptance

- [x] `pnpm db:generate` produces a clean migration adding only the
      `drafts` table + its indices.
- [x] `pnpm db:migrate` applies cleanly against a fresh DB.
- [x] `SqliteDraftStore.save(d)` then `load(d.draftId)` round-trips the
      `DraftCourseState` byte-equivalent (modulo the `lastTouchedAt`
      bump).
- [x] `load()` returns null for rows with `confirmedAt` or
      `discardedAt` set.
- [x] `listForStudent(studentId)` filters by student, excludes
      terminal rows, orders by `lastTouchedAt` DESC.
- [x] `markConfirmedTx` inside a rolled-back transaction leaves the row
      active (verify with a deliberate tx rollback in the test).
- [x] `markDiscarded` flips `discardedAt`; subsequent `load()` returns
      null.
- [x] `sweepStale(cutoff)` discards rows where `lastTouchedAt < cutoff`,
      leaves fresher rows untouched, returns the swept ids.
- [x] `pnpm typecheck && pnpm lint && pnpm test` green.

## Implementation notes

### Files changed

- `packages/core/src/schema.ts` — added `drafts` table with 8 columns and 2
  indices; registered in `coreSchema`. Used Drizzle `.$type<DraftCourseState>()`
  on `stateJson` so TypeScript understands the blob shape.
- `drizzle/0012_odd_rumiko_fujikawa.sql` — generated by `pnpm db:generate`;
  adds `drafts` table + `drafts_student_touched_idx` and `drafts_active_sweep_idx`.
- `packages/core/src/services/draft-store.ts` (new) — `DraftStore` interface +
  `SqliteDraftStore` implementation (130 lines).
- `packages/core/src/services/index.ts` — added exports for `DraftStore` and
  `SqliteDraftStore` (alphabetically sorted after `documents-service.js` to satisfy
  Biome's organizeImports rule).
- `packages/core/src/__tests__/draft-store.test.ts` (new) — 13 tests covering
  all acceptance criteria.

### Deviations from design

- **`save()` stores the caller's `lastTouchedAt` verbatim** (design said "bump to
  now on save"). The design's note "Caller supplies the new state" implies the
  caller is responsible for setting `lastTouchedAt` before calling `save()`. Bumping
  to `now` inside `save()` would make the sweep test impossible (stale drafts
  would always be saved with current timestamp). The integration story caller is
  expected to set `draft.lastTouchedAt = Date.now()` before calling `save()`;
  `touch()` provides column-only bump without blob re-serialization.

- **Migration landed as `0012_odd_rumiko_fujikawa.sql`** — the design expected
  `0009_*.sql` but migrations 0009–0011 were already present in the repo
  (course-documents, course-units/lesson-assessments/lesson-units, and a phase-16
  sessions column migration). This is correct and expected.
