Row 1 — single dense question. 70-word prompt + 5 choices ranging 9-33 words. This is the kind of question that would surface in a graduate-level chain-rule lesson, a textbook problem disambiguation, or a course-create draft review.
  • Wide: prompt and choices read cleanly; the 3 selected badge sits naturally between Submit and clarify-in-chat. Each choice is 1-2 lines.
  • Medium: tighter padding (from @container chat (max-width: 599px)) pulls the card inward; choices grow to 2-3 lines but the indicator stays anchored top-left. Free-form scales to width.
  • Narrow: action row stacks vertically per container query — Submit, the badge, and clarify each get their own row, full width. Choices wrap to 3-4 lines; the prompt is the densest block.

Row 2 — paged set of 4 questions. One question card wrapping the active question 3 of 4 (multi-select). Tab strip shows status across all four.
  • Wide: tab strip + progress label fit comfortably on one line in the head. Active question body has full breathing room.
  • Medium: tab strip stays one row; progress shortens to "3 of 4"; head padding tightens. Choices remain single-line for short answers.
  • Narrow: head still fits on one row (4 tabs is the sweet spot). Beyond 4 tabs the strip would wrap or need horizontal scroll — flag for design pass.

Where this still strains (input to feature-question-panel-rework design):
  • At narrow a 70-word prompt + 5 multi-line choices pushes the card past 700px tall — significant scroll. Schema caps below would prevent this from being agent-reachable.
  • The 3 selected badge in the action row wraps awkwardly at narrow. Worth considering whether the live-selected count belongs in the kicker (top) instead of the actions row (bottom).
  • Math notation isn't rendered via KaTeX in mocks — production rendering will be richer and heights will differ.
  • Beyond ~6 tabs in the paged set the tab strip would need a different chrome (horizontal scroll? compact pagination?). Currently undefined.

Tool-schema constraints recommended (input to feature-question-panel-rework design — consolidated to backlog as idea-inline-question-density-layout-and-schema-caps):
  • Prompt max ~50 words (~300 chars). Tutor uses the preceding chat turn for context; the prompt itself is the question, not the setup.
  • Per-choice max ~15 words (~80 chars). Long reasoning belongs in the chat turn; choices stay crisp.
  • Choice count cap: 5. Miller's 7±2 with the lower edge for active discrimination.
  • Multi-select hard cap: 6 choices; beyond that, single-select with a refining follow-up.
Schema errors should be descriptive so the agent learns the constraints by reading them, not by repeated rejections.
